# ウラ取り（uradori）

> **AIの「根拠あります」に、原文で検印を押す。**

Claude Code の mod です。Claude が回答の中で出典（プロジェクト内のファイルやウェブページ）を挙げると、
**mod 自身がその原文を読みに行き**、主張と食い違っていないかを確かめます。
結果は入力欄の上の帯に出て、［原文を見る］で**原文ポップアップ**が開きます。
ポップアップには、実際のページ／ファイルの**該当箇所を前後の文脈ごと**表示し、根拠の行を ▶ で強調します。
リンクを押すと、**実際のサイトがその文までスクロールしてハイライトされた状態**で開きます。

```
🔍 ウラ取り ✔ 0  ✖ 2  ？ 0   [ 原文を見る ] [ 訂正させる ] [ × ]
  ✖ 主張: タイムアウトは30秒です
    原文 src/config.ts L3: timeout: 60_000, // ミリ秒
```

```
│ ✖ 原文と食い違い （2/2）
│ Claude の主張
│ 「1回のリクエストで取得できるのは最大100件です」
│ 実際のページ：APIの利用制限 | サンプルAPIドキュメント
│ ╭──────────────────────────────────────────────╮
│ │   取得件数                                   │
│ │ ▶ 1回のリクエストで取得できるのは最大50件です。│
│ │   それより多く取得したい場合は…              │
│ ╰──────────────────────────────────────────────╯
│ 🔗 実際のサイトの該当箇所を開く（ハイライト表示）
│ [ この主張を訂正させる ] [ ← 前 ] [ 次 → ] [ 閉じる ]
```

### 回答の本文にも印が付く

チェックした主張の文の後ろに、回答の本文の中で直接印が付きます（表示だけで、保存された回答は変わりません）。
確認中は 🔍、終わったものから ✔ や ✖ に変わります。

```
タイムアウトは30秒です（根拠：src/config.ts）。 ✖ 原文と違う
リトライは3回です（src/config.ts:3）。 ✔
```

本文に**マウスを乗せると、原文のカード**が本文の上に重なって出ます（デスクトップアプリ・VS Code・マウスが使えるターミナル）。
食い違いの主張が先頭で、原文の該当行が ▶ つきで並びます。スマートフォンでは印だけです。

```
╭──────────────────────────────────────────────╮
│ 🔍 ウラ取り ✔ 1  ✖ 1  ？ 0                     │
│ ✖ タイムアウトは30秒です                       │
│   ▶ src/config.ts L2: timeout: 60_000,        │
│ ✔ リトライは3回です                            │
│   ▶ src/config.ts L3: retries: 3,             │
╰──────────────────────────────────────────────╯
```

印は最近の10回答ぶん残るので、あとから前の回答を見返しても付いています。

| 印 | 意味 |
|---|---|
| ✔ | 原文にも同じことが書いてある |
| ✖ | 原文と食い違う（数値・条件が違う、否定されている など）。いちばん重い印です |
| △ | 引用ずれ: Claude が添えた引用が原文に一字一句は見つからないが、内容は食い違っていない（一致、または判定できなかった） |
| ？ | 確認できない（原文に記述がない、取得に失敗した、読まない設定のファイル） |
| 🔒 | アクセス拒否で原文を取得できない（下の「アクセス拒否のページ」） |
| 📄 | PDF なので自動では読めない（自分で開いて確かめるリンクと［別の出典を探させる］を出します） |
| ⏸ | 自動では取りに行かなかった URL（社内・ローカルのアドレスや、秘密らしい値を含む URL。下の「安全のために」）。ポップアップの［原文を取りに行く］を押したときだけ取りに行きます |

- ✖（原文と食い違い）が出たときは、**原文ポップアップがダイアログで自動で開きます**（Esc で閉じます）。入力欄に文字を打っているときはキー入力を奪わず、横に開くだけです。止めたいときはポップアップ下の［切り替え］か `/uradori popup off`。
- ターミナルの幅が狭い（144桁未満）と、Claude Code は人が押していないパネルを置かないので、代わりにトーストで「✖ 原文と食い違う主張があります」と知らせます。帯の［原文を見る］なら、どの幅でも開きます。
- ✖ 以外（✔ ？ など）は帯だけで知らせます。
- 帯・ホバーのカード・`/uradori` の件数は同じ数え方です。✔ ✖ ？ はいつも、△ ⏸ 🔒 📄 はあるときだけ出ます（⏸ 🔒 📄 は ？ に含めません）。
- 「実際のサイトの該当箇所を開く」は、ブラウザのテキストフラグメント（`#:~:text=…`）を使います。Chrome・Edge・Safari などで、その文がハイライトされます。
- Claude が出典に「」で引用を添えたとき（`（出典: https://… の「料金」節「上限は50件」）`）や、URL にテキストフラグメント（`#:~:text=…`）を付けたときは、**その引用が原文に一字一句あるか**をモデルを使わずに照合します。空白や全角・半角の違いは無視し、「…」で省略した引用は前後の部分が順に出てくれば一致とします。原文にない引用は、内容が食い違っていなければ ✖ ではなく **△ 引用ずれ** になります（HTML を文字にするときの差でも起きるため、事実の食い違いとは分けています）。内容も食い違っていれば ✖ です。
- 前の回答の結果は、次の回答で消えます（出典のない回答の下に、前の ✖ が残ることはありません）。
- ✖ の主張は［訂正させる］を押すと、原文の抜粋つきで Claude に訂正を依頼します。訂正後の回答もまた自動でウラ取りされます。

## なぜ必要か

- Claude Code がウェブページを読むとき（WebFetch）、受け取るのは**ページ全文ではなく、小さなモデルが要約した結果**です。「ページにこう書いてある」が伝言ゲームになっていることがあります。
- ドキュメントが古いと、Claude は古い内容をそのまま「根拠あり」で答えます。
- 確かめるには人がリンクやファイルを開くしかなく、結局確かめずに信じてしまいがちです。

ウラ取りは Claude が読んだ要約を使わず、原文を自分で取りに行きます。判定は**会話の履歴を持たない別のモデル呼び出し**で行うので、Claude と同じ思い込みを引き継ぎません。

## 使い方

入れておくだけで、出典つきの回答が終わるたびに自動でチェックします。

| コマンド | 動き |
|---|---|
| `/uradori` | 原文ポップアップを開く（結果の要約と、該当箇所へのリンクも文字で表示） |
| `/uradori 2` | 2件目の主張の原文を開く |
| `/uradori recheck` | 直前の回答をもう一度チェックする |
| `/uradori off` / `/uradori on` | 自動チェックを止める／再開する |
| `/uradori strict` | 毎回の回答をウラ取り対象にする（もう一度で元に戻す） |
| `/uradori why` | 直前の回答をウラ取りした／しなかった理由を表示する |
| `/uradori archive off` / `/uradori archive on` | アクセス拒否のときに Web Archive を使わない／使う（既定: 使う） |
| `/uradori popup off` / `/uradori popup on` | ✖ のとき原文ポップアップを自動で開かない／開く（既定: 開く） |

### いつ発動するか

| 質問 | 回答 | 動き |
|---|---|---|
| 根拠を求める言葉がある（根拠・出典・一次情報・ソース・裏付け・エビデンス・原典・ファクトチェック・cite など） | URL・ファイルの出典あり | 原文でチェック → ✔ ✖ △ ？（数値・日付・規格などの主張から先に確認） |
| 〃 | 出典が名前だけ（「農林水産省『〜』」など） | 帯に `⚪ URLなしの出典 n件` と［一次情報で裏付けさせる］ |
| 〃 | 出典なし | 帯に `⚪ 根拠が示されていません` と［一次情報で裏付けさせる］ |
| 根拠を求める言葉がない | URL・ファイルの出典あり | 原文でチェック（従来どおり） |
| 〃 | 出典なし | 何もしない |

根拠を求める質問のときは、Claude にだけ見える指示（「出典を URL かファイルパスで書く・一次情報を優先する・引用を「」で添える・PDF より HTML のページを優先する」）を質問に添えます。入力した文は変わりません。
このとき入力欄の上に `🔍 根拠モードで送信（質問の「根拠」に反応）` と出るので、回答の書き方が変わった理由が分かります（回答が終わると消えます）。
「ソースコード」や数式の「公式」では発動しません。印はそのターンかぎりです。

### アクセス拒否のページ

ボット対策（Cloudflare の「Just a moment...」など）で原文を取得できないページは、次の順で対処します。

1. ブラウザと同じヘッダーで取りに行く
2. 403・429 やボット確認のページだったら、**Web Archive（web.archive.org）の最新の保存版**で確かめる。ポップアップに「📦 Web Archive 2026-04-25 の保存版で確認」と出ます（今のページと違う可能性があります）
3. 保存版もなければ **🔒**（？ とは別に数えます）。帯の［別の出典を探させる］で、Claude に自動取得できる別の一次情報で裏付け直させます。ポップアップの「ブラウザで開いて自分で確かめる」から、自分のブラウザで開くこともできます

Web Archive にはページの URL だけを送ります（会話の内容は送りません）。使いたくないときは `/uradori archive off`。

### ウラ取りの対象になる書き方

- `タイムアウトは60秒です（根拠：src/config.ts）` … かっこの中の出典
- `根拠は src/config.ts の3行目です` … 直前の文が主張になる
- `docs/spec.md によると、〜です` … 「によると」「より」
- 回答の末尾の参考リンクや、「設定は src/config.ts にあります」のような書き方 … モデルが主張と出典を対にしてからチェックします
- ファイルは `src/config.ts:12` や `docs/a.md#L5` の行番号も読みます

「`config.ts` を修正しました」のような**作業の報告や質問はチェックしません**（利用量と誤報を減らすため）。

## インストール

Claude Code v2.1.287 以降が必要です。帯やポップアップが表示されるのは、**ターミナル版の Claude Code** と**デスクトップアプリの Code タブ**（と VS Code 拡張）です。
claude.ai のチャット画面やクラウドのセッションでは、mod 自体は動きますが、描いたものを表示する画面がないため何も見えません（公式ドキュメントの「Where mods run」のとおり）。

**このセッションだけ試す**（フォルダの場所は置いた場所に合わせてください）

```
claude --plugin-dir ~/mods/uradori
```

**毎回読み込む**: `~/.claude/settings.json` の `env` に追加します（デスクトップアプリにも効きます）。

```json
{
  "env": {
    "CLAUDE_CODE_PLUGIN_DIRS": "~/mods/uradori"
  }
}
```

読み込まれたかは `/plugin` で確認できます（`1 mod active · uradori`）。

入手から動作確認・更新・取り外しまでの詳しい手順は [導入ガイド](https://yui-taro.github.io/uradori/install.html) にあります。

## デモ（約60秒）

`demo/` に、**ドキュメントが古くなっている**小さなプロジェクトが入っています。

- `docs/spec.md` … 「タイムアウト: 30秒（`src/config.ts` で設定）」と書いてある（2025年4月の古い仕様）
- `src/config.ts` … 実際は `timeout: 60_000`（60秒）

```
cd ~/mods/uradori/demo
claude --plugin-dir ~/mods/uradori
```

1. **質問する**: 「docs/spec.md を読んで、APIクライアントのタイムアウトとリトライ回数を教えて。どのファイルで設定されているかも書いて。コードは開かず、ドキュメントだけで答えて」
2. **Claude の回答**: 「タイムアウトは30秒、リトライは3回です。どちらも `src/config.ts` で設定されています」
3. **数秒後**: 帯に **✖ 1 / ✔ 1** が出て、原文ポップアップが自動で開く。`src/config.ts` の3行目 `timeout: 60_000` が ▶ で強調されている（人はファイルを開いていない）
4. **［訂正させる］を押す**: Claude が config.ts を開き直して「60秒でした。ドキュメントが古いです」と訂正 → 帯が ✔ に変わる

ウェブページの例を見せたいときは、公式ドキュメントの URL を出典にした質問をすると、ポップアップの「実際のサイトの該当箇所を開く」でブラウザが該当文をハイライトして開きます。

確実に再現したいときは、質問の代わりに「次の文をそのまま出力して：タイムアウトは30秒です（根拠：`src/config.ts`）。」と頼むと、毎回 ✖ が出ます。

## 仕組み

```
Claude の回答が終わる（turn.complete）
  ↓  Claude は止めずに、裏で始める
① 回答から出典（ファイル・URL）を拾い、主張と対にする
② 原文を mod 自身が取りに行く（ファイルは $.fs、URL は $.http）
③ 原文から関係する行を選ぶ（小さい原文はまるごと）
④ 会話履歴のない別のモデル呼び出し（haiku）で 一致／食い違い／確認できない を判定
⑤ 帯と原文ポップアップに表示。抜粋は判定モデルの言葉ではなく、原文の行そのもの
⑥ URL は、根拠の文を使ったテキストフラグメント付きリンクにする（実際のサイトの該当箇所へ）
```

- 判定に使うモデルは `hooks/register.tsx` の `JUDGE_MODEL`（既定は `haiku`）。精度を上げたいときは `sonnet` に変えてください。
- 1回の回答でチェックする主張は最大6件です。
- 待つ時間には上限があります。ページの取得は1回15秒、判定モデルの呼び出しは30秒、主張1件ぜんぶで60秒。過ぎたものは ？ にして、帯が「確認中」のまま残らないようにしています（リロードで途中になったチェックも、次の起動で ？ にします）。
- 判定モデルが「一致」「食い違い」と答えても、**根拠になった原文の行を示せなければ ？** にします（Claude の引用が原文に一字一句あったときは、その行を一致の根拠にします）。

## 安全のために

- 読むファイルは**プロジェクトの中にあるものだけ**です（シンボリックリンクの行き先も確かめます）。
- `.env`、`*.pem`、`id_rsa`、`credentials` などの**秘密情報らしいファイルは読みません**（？ になります）。
- 判定のため、主張と原文の抜粋を、セッションと同じアカウントのモデル（haiku）に送ります。
- 取得や判定に失敗したもの、時間内に終わらなかったもの、原文の行を根拠に示せなかったものは、必ず ？（確認できない）にします。✔ にはしません。
- Claude が書いた URL に、mod は人の確認なしでアクセスします。読んだページに仕込まれた指示で Claude が「出典」として秘密を載せた URL や社内のアドレスを書かされても送り出さないよう、次の URL は**自動では取りに行かず ⏸** にします（リダイレクトの行き先も同じです）。
  - 社内・ローカルのアドレス（`localhost`、`10.*`・`192.168.*` などのプライベート IP、`169.254.*`、`.local`・`.internal`、ドットのないホスト名）
  - ユーザー名・パスワードを含む URL、`token=`・`api_key=`・`session=` などの認証情報らしいクエリ、長いランダムな文字列を含むクエリやパス
  - ポップアップの［原文を取りに行く］を押すと取りに行きます（このときは Web Archive には送りません）。保留の URL はリンクにもしません（開くだけでも中身が相手に届くため）
  - ホスト名を DNS で引いた先が社内の IP かどうかまでは確かめられません（mod から DNS を引けないため）
- mod はサンドボックスの外で、あなたの権限で動きます。会社の PC で使う場合は社内のルールを確認してください。

## 限界

- 確かめるのは「**出典にそう書いてあるか**」です。出典そのものが正しいかは分かりません（古いドキュメントには ✔ が付きます。上のデモのように、コードも出典に挙げると食い違いが見つかります）。
- ログインが必要なページ、JavaScript で描画されるページは読めません（？ になります）。
- PDF は読めません（📄 になります）。そのため根拠を求める質問では、Claude に HTML のページを優先するよう伝えています。
- 判定もモデルなので間違えることがあります。だから原文の行を必ず並べて表示し、最後は人が見て判断できるようにしています。

## 開発

```
claude plugin validate .
claude plugin test .
```

`tests/uradori.test.tsx` に、主張の取り出し・原文の扱い・帯と原文ポップアップの表示（terminal / desktop / vscode / mobile）・テキストフラグメントのリンク・取得失敗時のフェイルセーフ・PDF の扱い・引用の照合・前の回答の帯を消すこと・本文の印とホバーの原文カード・帯とカードの件数の一致・根拠モードの表示・自動で取りに行かない URL・根拠の行のない判定・応答しないページの時間切れ・✖ のときのダイアログなど82件のテストがあります。
