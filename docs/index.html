CLAUDE CODE MOD

ウラ取りuradori v0.4.0

AIの「根拠あります」に、原文で検印を押す。

Claude が回答で出典（プロジェクト内のファイルやウェブページ）を挙げると、mod 自身がその原文を読みに行き、主張と食い違っていないかを確かめます。結果は入力欄の上の帯に出て、原文の該当行を見ながら人が最終判断できます。

なぜ必要か

「根拠あり」が伝言ゲームになる場面があるため。

WebFetch は要約を返す

Claude Code がウェブページを読むとき、受け取るのはページ全文ではなく小さなモデルが要約した結果です。

古いドキュメントをそのまま信じる

ドキュメントが古いと、Claude は古い内容を「根拠あり」として答えてしまいます。

人が確かめるのは手間

リンクやファイルを自分で開くしかなく、結局確かめずに信じてしまいがちです。

ウラ取りの答え

Claude が読んだ要約を使わず、原文を自分で取りに行きます。判定は会話の履歴を持たない別のモデル呼び出しなので、Claude と同じ思い込みを引き継ぎません。

仕組み

回答が終わった瞬間から、Claude を止めずに裏で動きます。

きっかけ：Claude の回答が完了する（turn.complete イベント）。サブエージェントの回答や空の回答は対象外。$.clock.after(0, …) で処理を後回しにし、会話の進行をブロックしません。

出典を拾い、主張と対にする正規表現 + $.model

かっこ内の出典、「〜によると」「根拠は〜」などの書き方は文から直接取り出します。末尾の参考リンクのように対応が曖昧なものは、モデルに主張と出典を対にさせます。行番号（:12、#L5）も読みます。

原文を mod 自身が取りに行く$.fs / $.http

ファイルはプロジェクト内かどうか、秘密情報らしい名前でないかを確かめてから読みます。URL は HTML を本文テキストに変換し、ページタイトルも取ります。

関係する行を選ぶ

原文が 24,000 文字以内ならまるごと。大きいときは主張のキーワード（60_000→60000 のように正規化）と行番号を手がかりに抜粋します。

まっさらなモデルで判定$.model.complete (haiku)

会話履歴のない呼び出しに、主張・出典・行番号つき原文だけを渡し、match / mismatch / unknown と根拠行番号（最大3つ）を JSON で返させます。単位換算や表記揺れは同じ値として扱います。

帯とポップアップに表示ui.render / $.ui.open

表示する抜粋は判定モデルの言葉ではなく、原文の行そのもの。⚠ があればトーストで知らせ、ポップアップを自動で開きます。

ハイライトリンクを作る

URL の場合、根拠の文からテキストフラグメント付きリンクを作ります。80文字を超える文は先頭と末尾の24文字で範囲指定します。

1回の回答でチェックする主張は最大6件。判定モデルは hooks/register.tsx の JUDGE_MODEL（既定 haiku）で、精度を上げたいときは sonnet に変えられます。

対象になる書き方

作業報告や質問はチェックしないことで、利用量と誤報を抑えています。

✔ チェックする

  • タイムアウトは60秒です（根拠：src/config.ts）
  • 根拠は src/config.ts の3行目です（直前の文が主張）
  • docs/spec.md によると、〜です
  • 回答末尾の参考リンク、「設定は src/config.ts にあります」

— チェックしない

  • 「config.ts を修正しました」のような作業の報告
  • 質問文
  • example.com のようなドメイン名だけ、1.2.3 のようなバージョン番号

安全設計と限界

迷ったら ✔ にしない、が原則。

安全のために

  • 読むのはプロジェクト内のファイルだけ（シンボリックリンクの行き先も確認）
  • .env、*.pem、id_rsa、credentials など秘密情報らしいファイルは読まない
  • 2MB超・バイナリのファイルは読まない
  • 取得や判定に失敗したものは必ず ✖。✔ にはしない
  • 主張と原文の抜粋を、セッションと同じアカウントの haiku に送る
  • mod はサンドボックスの外であなたの権限で動く。会社 PC では社内ルールを確認

限界

  • 確かめるのは「出典にそう書いてあるか」。出典自体の正しさは分からない（古いドキュメントにも ✔ が付く）
  • ログインが必要なページ、PDF、JavaScript で描画されるページは読めない
  • 判定もモデルなので間違えることがある。だから原文の行を必ず並べて見せる

導入とデモ

約60秒で「古いドキュメント」を見抜く様子を試せます。

claude --plugin-dir ~/mods/uradori # このセッションだけ試す // ~/.claude/settings.json に書くと毎回読み込む { "env": { "CLAUDE_CODE_PLUGIN_DIRS": "~/mods/uradori" } } /plugin # → 1 mod active · uradori

demo/ には、docs/spec.md に「タイムアウト30秒」と書かれているのに、実際の src/config.ts は timeout: 60_000（60秒）という、ドキュメントが古いプロジェクトが入っています。

ドキュメントだけで答えさせる

「docs/spec.md を読んで、タイムアウトとリトライ回数を教えて。どのファイルで設定されているかも書いて。コードは開かず答えて」

Claude が古い情報で回答

「タイムアウトは30秒、リトライは3回。どちらも src/config.ts で設定」

1〜2秒後に ⚠ 1 / ✔ 1

ポップアップが開き、src/config.ts の3行目 timeout: 60_000 が ▶ で強調される。人はファイルを開いていません。

［訂正させる］

Claude が config.ts を開き直して「60秒でした。ドキュメントが古いです」と訂正し、帯が ✔ に変わります。
